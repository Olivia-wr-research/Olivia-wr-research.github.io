# TERRAFAR 信息架构探索｜10 卡 × 5 人先导研究

**状态：研究工具已实现，真实参与者尚未招募；不得把模拟测试写作已完成的用户研究。**

- [参与者首页](https://olivia-wr-research.github.io/apps/terrafar-card-sort/)（正式发布后）
- [研究者分析入口](https://olivia-wr-research.github.io/apps/terrafar-card-sort/?mode=research)（正式发布后）
- 对照产品：[TERRAFAR](https://olivia-wr-research.github.io/apps/application-board/)

## 研究问题和边界

**问题**：首次接触 TERRAFAR 的目标用户如何自然地组织学习/科研机会探索、研究团队资料、对比收藏、申请管理等十项信息？哪些卡被频繁放在一起，哪些归属模糊？

本次采用 **开放式卡片分类**。参与者先分为 2–6 组，完成分组后自定义组名（不预先提供「发现机会」「申请管理」等类别）。卡片顺序按匿名编号分别固定打乱，避免五个人看到完全相同的顺序。附加询问最难归组的卡片、原因、主观难易程度。

本次只作为低成本**定性先导研究**。5 人不足以据此确认新信息架构可靠，也不适合据此计算总体百分比或显著性。NN/g 关于卡片分类的建议通常至少 15 名定性参与者；后续需要更广泛样本和树测试验证可发现性。

不讨论哪个功能更受欢迎、不测任务完成率、不评价远境总体易用性，也不能把卡片分类结果单独解释成用户行为因果关系。

## 十张卡片（核对自 2026-11-19 的现有产品结构）

| ID | 功能 |
|---|---|
| C01 | 查看硕士项目与入学要求 |
| C02 | 了解博士项目及资助情况 |
| C03 | 寻找研究助理、博士后或教职岗位 |
| C04 | 按国家、研究方向和截止日期缩小结果 |
| C05 | 了解研究者和研究团队在做什么 |
| C06 | 按个人兴趣和研究方法发现相关机会 |
| C07 | 核对机会的官方来源及信息状态 |
| C08 | 把多个机会放在一起比较 |
| C09 | 收藏感兴趣的机会 |
| C10 | 记录申请进度和准备材料清单 |

**功能边界**：2026-11-19 的 `docs/apps/application-board/features.mjs` 中 `CV_MATCH_ENABLED=false`，简历导入/相关引导暂时停用。因此没有把它们列为「现有可用功能」进入卡片测试。C06 指已存在的手动兴趣/方法档案与相关机会探索，不指 CV 自动解析。

## 招募与执行

**理想目标用户**（便利抽样且如实披露，避免全是朋友或产品开发者）：
- P1、P2：近期有海外硕士或博士申请需求的人
- P3、P4：近期有科研岗位/研究组发现需求的人
- P5：同时涉及升学和科研就业探索的人

每人使用研究者分析页生成的一个独立链接 `?p=1` 到 `?p=5`。参与者不要事先看远境的导航，独立完成，避免交流答案。

**对参与者的简短邀请文案**：

> 我在为一个海外升学与科研机会网站做信息架构试测，想请你花约 5–8 分钟把 10 张功能卡按照自己的理解分组并命名。没有标准答案，不需要登录，也不会上传简历。完成后请把生成的 `TFIA1:` 结果码发给我。你可以随时退出或不发送反馈。

## 数据收集与分析

本项目为纯静态网页，不连接 Umami、数据库或任何远端收件箱：
1. 参与者在自己浏览器中完成卡片分组，数据仅写入当前会话的 `sessionStorage` 用于防意外刷新。
2. 提交前没有服务器收集行为；完成后得到唯一匿名结果码 `TFIA1:...` 或下载一个 JSON。
3. 参与者自愿通过聊天软件向研究者发送结果码；研究者打开 `?mode=research`，每行粘贴一份。
4. 分析页只在本地解码、合并 P1–P5、检查重复与格式，输出原始分组、匿名备注、成对共组矩阵及 CSV 明细。
5. 如果 P1–P5 不完整，必须报告实际有效样本量。编号重复取最后一份并报警；不把同一个参与者的重复结果计成多人。
6. 自定义组名没有自动归一化，不应直接将同义栏目计为不同潜在构念，也不应事后为了迎合既有导航而重命名用户原话。

**不收集**：姓名、邮箱、学位证明、简历、申请记录、Cookie ID、IP 地址（网页本身不主动收集；GitHub Pages 正常 Web 托管仍可能记录必要的服务器访问日志）。结果码中的自填自由文本由参与者决定，提示不要写隐私。

## 分析框架与决策门槛

先检查：招募结构和是否独立完成、缺失卡片、重复结果、每人组数、用时、困难卡片及原因。再看：
- **共组矩阵**：对任意一对卡，统计被放进同一组的参与者数（0–n），不是概率。
- **命名趋向**：保留参与者原词，在明示规则下人工归纳语义近似的标签，记录异议。
- **歧义卡**：结合分组分歧和原话评估是否应改写标签、跨栏目加入口或调整导航。
- **产品方案**：提出 1–2 个备选导航结构，并设计目标任务树测试。不能仅依据 5 人做上线决策。

## 作品集表述

在尚未收齐数据前，可以写：*“为 TERRAFAR 设计并实现一项开放式卡片分类先导研究（10 卡、计划招募 5 位目标用户），实现匿名反馈收集、共组矩阵与 CSV 导出。”*

等真实完成后，才可以写真实有效样本量、观察到的类别和原话，并完整披露便利抽样、测试局限和后续验证计划。
