# TERRAFAR 安全持久化与跨日恢复方案

核查日期：2026-10-25（北京时间）。基线：PR #9 的 `82311772328ab380636fdeb7719fc41291ba8176`。

## 结论与本次边界

推荐 **独立私有执行仓库 + 私有、开启版本控制的 Amazon S3 专用桶**。公开网站仓库保留代码及另行允许公开的汇总；完整候选、页面正文、用户决定和审核历史只进入获授权的私有存储。公开仓库现有授权门禁不变。

本次只提交代码、离线合成测试、未启用的工作流示例和本文。没有创建云资源、设置授权变量、读取真实密钥、上传真实档案、运行来源采集、合并 PR 或发布网站。`private-maintenance.yml.example` 不是活动工作流。以下私有目的地仍需所有者指定和批准。

## 方案比较

| 方案 | 谁可访问 | 成本 | 历史与恢复 | 故障、保留风险 | 用途判断 |
|---|---|---|---|---|---|
| 私有 S3 版本化对象存储 + 私有执行仓库 | 所有者和限定前缀的运行角色；GitHub 仓库权限不自动授予 S3 权限 | 存储量、请求、出站流量、可选审计/复制费；私有运行分钟另计 | 固定版本 ID、加密清单和条件更新指针；旧版本可人工审查后恢复 | 错配生命周期、账号关闭、欠费、密钥丢失、管理员删除；需独立备份 | 首选；本次实现 AWS S3 适配 |
| 私有 GitHub 仓库中的 Actions 产物 | 该私有仓库有读取权限的人；无单个产物的所有者专享权限 | 使用 Actions 存储与运行额度，超额计费 | 可按确切运行/产物 ID 恢复 | 默认 90 天；私有仓库可配置最长 400 天且受上级限制；运行/产物被删或过期会断链 | 临时人工交付或迁移中转，不能单独做永久状态库 |
| 私有 Git 仓库保存加密快照 | 仓库读者；密钥再单独控制 | 小规模可能无额外仓库费用；大二进制、LFS 和自动化另计 | 原子提交、历史版本清楚；CAS/非强推可防一般竞争 | 密文每次变化导致仓库膨胀；克隆者保留历史；改为公开会暴露全部密文；删除/强推风险 | 可做小账本备份，不适合每日大量页面证据 |
| 所有者 NAS/服务器 + 加密磁盘 + 异地备份 | 所有者和受控服务账户 | 硬件/主机、电费、运维和备份成本 | 本地数据库事务 + 定期加密备份 | 离线、硬盘故障、补丁、网络和备份恢复均需自己负责 | 不接受云托管时的备选；本次未实现 |
| 私有托管数据库 + 对象存储 | 数据库角色与存储角色分别控制 | 数据库最低套餐、连接、备份及对象存储费 | 审核事务适合数据库；大证据仍放对象存储 | 两处提交需 outbox/事务协调，复杂度更高 | 规模增加后再考虑，本次不引入 |
| 公开仓库的分支、Release、Actions 产物、缓存 | 仍在公开仓库读取边界内 | 公开标准运行器可能免费，但不提供私有边界 | 产物/缓存还会过期或驱逐 | 加密不等于私有访问；当前完整材料公开目的地未获批准 | 不采用，不设置公开归档批准变量 |

GitHub 文档明确：登录且有仓库读取权限者可下载产物；公开仓库产物因此不能视为“仅所有者可读”。[下载权限](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)、[保留期限](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository)。

成本估算应基于实测日增量，不能把当前 312 KB 历史产物外推为未来每日证据体积。示例：按特定地区 Standard 单价 0.023 美元/GB·月，10 GB 仅存储约 0.23 美元/月；请求、版本、下载流量、备份和私有执行费用另计，不是总价承诺。以选定地区的[官方定价](https://aws.amazon.com/s3/pricing/)为准。GitHub Free 目前含每月 2,000 分钟和 500 MB 产物额度；每日 60 分钟约 1,800 分钟，每日 90 分钟约 2,700 分钟，还未计其他工作流。[Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。

## 新代码怎样保存和恢复

`scripts/terrafar_private_store.py`：

1. 必须是所有者明确启用的私有执行目的地；默认停止。检查桶所有者、公有访问全阻止、非公有策略、版本控制、禁用 ACL。发现启用的到期删除或冷存储迁移规则即停止。
2. 保持当前证书。保存前用现有密钥完成一次加密解密自检；没有匹配密钥则不写入任何新对象。
3. 对每个普通文件使用现有 CMS 格式加密，生成不可变对象；读回密文并校验。未变化文件复用原对象的精确版本 ID。
4. 将全部文件名、明文哈希、来源登记表、候选和审核历史的对象引用装入**加密清单**。完整资料不进入公开产物或公开分支。
5. 所有对象上传完成后，使用 `If-Match` 原子更新唯一的 `latest.json`；首次初始化单独使用 `If-None-Match: *`。每个版本记录序号和上一指针摘要。
6. 恢复必须读取当前指针并逐个校验精确版本；全部验证成功后，才把暂存目录整体交给后续程序。恢复生成的凭据必须与保存时的当前指针一致。
7. 登记表原字节不变；保留候选 ID 和既有审查历史前缀；审核日志必须是旧日志的单调扩展；历史子目录文件不得消失或改写。响应 `index.jsonl` 仅允许保留全部旧字节的追加。改登记表或实现版本需要另行审核迁移，不能静默接受。

`scripts/terrafar_private_cycle.py` 将日检和人工决定导入接到同一份私有状态：恢复 → 校验登记表/实现版本与未确认交付 → 日检或导入 → 保存证据/报告 → 单次提交。它不调用旧公开报告分支的加载/发布函数。人工输入仍由原有审核逻辑检查版本、样本和实际决定；不会自动生成用户通过。通过 GitHub 元数据检查失败的人工导入运行；没有持久回执就阻止下一轮日检，防止丢掉一次反对意见。已持久化的同一运行不重复导入；最早失败的导入可先重试恢复。错误/无法重放的交付须由所有者审查并单独做前向迁移，不能伪造回执清除门禁。

本实现继续兼容现有 CMS（RSA 接收者封装、AES-256-CBC）。CMS EnvelopedData **不是发送者签名**；哈希也不是签名。可信度来自私有存储的 IAM、不可变精确版本、读回校验和受保护代码。它防一般断链、损坏和竞争，不声称能阻止控制云账号或主分支的恶意管理员。所有者应另存已接受指针摘要与密钥备份，定期做异地恢复演练。

当前工程限额：单文件 32 MiB、加密清单明文 16 MiB、每快照最多 20,000 个文件。解包也限制体积和条目数。**这是一条有容量上限的实现，不是无限留存系统**。启用前必须对真实数据和预计保留期做容量/时长测试；达到 80% 应提前告警并做分层清单/按需恢复迁移。现在不会自动分片、压缩历史或删除证据来绕过上限。逐文件恢复的耗时和请求数随历史增长，需要在私有 90 分钟运行窗口内实测；若不满足，应先扩展分页清单及按需证据加载，再开启长期日检。

## 权限配置（所有者执行；本次未配置）

- 新建一个明确批准的私有执行仓库，只安装本示例工作流及审查后的必要代码；不要照搬其他公开发布工作流。关闭不需要的协作者访问，保护 main，禁止未经审核的代码进入持有密钥的运行。不要向 PR 任务或 `pull_request_target` 提供密钥。
- 创建专用 S3 桶，指定账户、地区和前缀；全部 Public Access Block=true，Versioning=Enabled，BucketOwnerEnforced。桶策略必须非公有并拒绝非 TLS。当前前缀不得设置自动过期/永久删除/归档转换。预算告警与独立备份需由所有者决定。
- AWS 使用 OIDC 临时凭据；信任条件精确限定 `aud=sts.amazonaws.com` 和 `sub=repo:所有者/私有执行仓库:ref:refs/heads/main`，不要用通配仓库/分支。示例未设置 environment，因设置 environment 会改变 OIDC subject；若另加 environment，需同步修改信任并设置分支限制。[官方说明](https://docs.github.com/actions/deployment/security-hardening-your-deployments/configuring-openid-connect-in-amazon-web-services)。
- 日常角色：桶级 `GetBucketPublicAccessBlock`、`GetBucketPolicyStatus`、`GetBucketVersioning`、`GetBucketOwnershipControls`、`GetLifecycleConfiguration` 和 `ListBucket`；对象级仅批准前缀的 `GetObject`、`GetObjectVersion`。允许 `objects/*` 上带 `If-None-Match` 的 `PutObject`；只允许 `latest.json` 上带 `If-Match` 的 `PutObject`。**不授予 DeleteObject/DeleteObjectVersion、修改桶策略、停用版本、改生命周期、公开 ACL 或 IAM 管理权限**。
- 首次初始化另由所有者控制的临时角色允许 `latest.json` 的 `If-None-Match` 写入，初始化验收后撤销此权限；日常角色不能创建丢失的指针。[条件写官方说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)。
- 私有仓库变量：`TERRAFAR_PRIVATE_STORAGE_APPROVED=true`、`TERRAFAR_STATE_BUCKET`、`TERRAFAR_STATE_PREFIX`、`TERRAFAR_AWS_ACCOUNT_ID`、`TERRAFAR_STATE_ROLE_ARN`、`TERRAFAR_STATE_REGION`。这些是私有目的地授权，不是公开档案授权。
- 私有仓库 secret：原证书对应的 `TERRAFAR_STATE_DECRYPTION_KEY`，由所有者在设置界面写入。不要贴进聊天、PR、命令参数、运行日志或提交。保留独立离线备份；不会生成新证书替换旧证书。
- `.example` 在上述条件完成前保持不启用。启用时文件名必须是 `.github/workflows/terrafar-private-maintenance.yml`，供交付身份检查精确匹配。不要设置 `TERRAFAR_PUBLIC_ENCRYPTED_ARCHIVES_APPROVED`；不放宽公开工作流现有门禁。

3. 在 2027-01-22 19:05:05 前，用精确运行 40088463064、产物 12557829387 及 `migrations/current.json` 已绑定的提交/证书/密文/清单摘要下载和验证原包。先保留原密文、原清单和来源元数据，再解密；不得改写原绑定来接受其他包。
4. 使用现有 `terrafar_restore_run_state.py` 的审查后迁移路径恢复来源状态和候选账本。另行取得较早的 160 条历史重建材料及任何真实审核决定/交付回执。对各包分别登记来源、ID 集合、事件数和哈希；二者不是同一时点的账本。
5. 按既有 reconcile/历史扩展规则合并；出现分歧立即停止供所有者审查，不能挑一份覆盖另一份。将旧包原字节放入 `legacy/`，完整历史运行目录放入 `runs/`。留存 411 个 ID、所有候选 ID、排除/失败/通过的历史决定；160 条待重核和 pending 抽检保持原状态。

9. 所有者确认私有保存及恢复合格后才启用日程。内容核验、160 条重核、真实用户抽检和网站发布继续是独立条件；存储上线不授予发布许可。

## 故障处理与保留

| 失败 | 自动行为 | 所有者/维护者处理 |
|---|---|---|
| 缺密钥、不匹配、证书变化 | 停止，不生成替代密钥或新权威 | 恢复原 key；确认现有证书；禁止把 key 写日志 |
| 断网、403、限流 | SDK 有限重试，随后停止 | 修复网络或角色；不得改公开存储兜底 |
| 部分对象上传失败 | 不更新指针；旧版本完整可用 | 重试新运行；未引用对象是孤儿，待单独审查清理 |
| 指针竞争/旧恢复凭据 | CAS 拒绝；不强推、不合并覆盖 | 重新恢复最新状态再处理；确认较新的用户决定仍在 |
| 写成功但响应丢失 | 只在精确读回等于本次指针时承认成功 | 其他情况停止，核对当前指针，不盲目重放 |
| 当前对象版本缺失/损坏 | 不回退至旧产物或空日志 | 从独立备份恢复**同一版本和事件链**，或经审查生成新的前向恢复版本 |
| 流程出错但状态仍合法 | 保存合法部分工作/日志，运行仍报告失败 | 重试前检查当前审核状态；失败不等于检查成功 |
| 运行器被强制终止 | 上次已提交状态保留；本轮未提交工作可能丢失 | 按运行回执重做本轮；当前恢复点目标最多一个运行周期，不承诺零丢失 |
| 文件/清单/时长接近上限 | 不删除历史或放宽校验 | 提前做分层索引、分区与按需加载工程；验收前不启用长期任务 |

开启版本控制不等于无限备份：生命周期可以永久删除旧版本，[AWS 官方说明](https://docs.aws.amazon.com/AmazonS3/latest/API/API_NoncurrentVersionExpiration.html)。当前所有被最新或保留快照引用的版本都不得按年龄自动删除。垃圾回收、到期删除、复制到另一账户/地区和 Object Lock 均需要独立方案及授权，本次代码不执行删除。

建议预算：完整候选/决定长期保留，页面证据先按所有者选定的 12 个月或更长时间规划；此处是待决政策，不是已设定的保留期。若采用对象锁，应另行评估不可提前删除的成本和隐私删除需求。每月校验备份可读性和容量，每季在隔离环境演练恢复；启用后 26 小时无新序号应报警，但本次未创建提醒或外发通知。
